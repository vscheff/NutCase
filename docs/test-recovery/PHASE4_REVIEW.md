# Phase 4 review - production workflow and drawing configuration

> Historical review: the requested directory cleanup removed archived development outputs, regression suites, synthetic fixtures and investigation scripts. Artifact paths and test commands below record earlier work; they are not all present in this runtime-focused directory. Current usage is in README.md; preservation and post-cleanup checks are in [docs/CLEANUP.md](docs/CLEANUP.md).

Phase 4 is implemented and executed on the installed FreeCAD 1.1.4 / bundled Python 3.11.14 environment. Native analysis, source measurements and TechDraw creation remain in FreeCAD. The production orchestrator, normalization and independent PDF verification run in external Python with pypdf 6.10.0, PDFium, Pillow and Poppler. No installed FreeCAD files or bundled dependencies were modified.

## Operating the generator

Use `scripts/generate-fastener.ps1 -InputFile PATH -Config config/comprehensive.json`. Set `FASTENER_PDF_PYTHON` or `-PdfPython` to an external environment, or create `.venv-pdf` and install `requirements-pipeline.txt`. Poppler is discovered on PATH or supplied explicitly. The tested launcher discovers FreeCAD through the existing registry/PATH/probed-installation workflow. The README documents all arguments, schema fields, catalog preparation and recovery.

The pipeline analyzes geometry and validates saved source references, runs native drawing creation and persisted association/material checks, retains the native PDF, normalizes a separate PDF, verifies it with two renderers, and publishes a complete versioned release through an atomically replaced current manifest. Exit 2 means a complete preliminary drawing requiring review, not an export failure.

## Publication behavior and faults resolved

The authoritative publication is `output/<stem>.current.json`, pointing to a complete release. Staging/native artifacts and diagnostics remain in `runs/<run id>/`. Existing root Phase 3.2 PDF/project files were not replaced; their hashes remain unchanged. A transaction across multiple ordinary filenames is not atomic on Windows, so no independently rewritten aliases are offered as a complete release.

The long FC00AAB13125 filename exposed MAX_PATH: a successful directory rename could leave its longer child paths unreadable. Release buckets now use a short readable prefix plus a stem hash, while actual artifact filenames remain intact. Every final artifact is read and hash-checked after directory placement, before the manifest commit. Excessively long requested output paths fail with a shorter-directory diagnostic. An orphaned complete candidate can remain after a commit failure; the previous manifest remains current. Experimental long-path releases and failed-run diagnostics are retained for diagnosis and are not current.

Fault-injection controls cover failed native export, a genuinely truncated native PDF, failed independent rendering, manifest replacement denial, unreadable final child paths and concurrent publication. Each prevents a new current release. The initial matrix harness also had an mm-only comparison key for angles; it was corrected to compare native degrees. Earlier harness logs are retained as attempts 1 and 2, not counted as successful tests.

## Configuration and verification

Basic selects overall length, source-supported external diameters, the smallest coaxial bore, across-flats and terminal enlargement geometry. Comprehensive preserves the existing nonredundant candidate behavior. Custom starts empty and selects explicit source identities; inclusion/exclusion also override the other modes. Every requested characteristic still passes independent native source, projection, persistence and presentation verification. Unsupported, missing-view and redundant candidates stay reported; selection never forces a guessed dimension.

Saved IDs use native geometric fingerprints of source face/edge evidence and supported measurements, replacing transient source numbering. Full-source binding and candidate membership are validated before any dimension is created. Native projected Edge indices remain internal current-run associations checked against source geometry, never user selections. Fingerprints include pose, trims, topology and native parameter/probe evidence; harmless re-export or importer changes can require review. They are conservative validation fingerprints, not a mathematical shape-equivalence proof. Numerical thresholds are not manufacturing tolerances.

Actual controls show: unchanged imported geometry with changed STEP serialization bytes preserves custom selections; a different constructed cylinder under the same filename rejects the old configuration before drawing; missing saved candidate identities reject on both supplied models; regeneration without a config reuses published custom policy; suppressed candidates stay suppressed. The additional optional-view control disables all optional views, selects fixed ANSI B and 2.5:1 scale, supplies reviewed axis/up and metadata, and excludes overall length. Missing dimensions after view suppression are retained as unresolved rather than forced into unrelated edges.

Human review JSON/Markdown lists every candidate, its measured value, selection, source status, native creation/verification and unresolved reason. It also includes measured features, semantic role inferences, unmapped faces and complete source validation. Source-bound custom examples for both supplied parts are in `config/examples/`. Values, tolerances and manufacturing functions cannot be overridden through configuration.

## PDF and rendered review

Every release was normalized automatically. Native section exports required the retained two Phase 3.2 corrections: 18 pathless closepath operations and 3 malformed RGB stroking commands. The optional no-section control required only the closepath correction. The normalized PDFs preserve valid operators/positions, resources, embedded fonts/glyph mappings, extracted text, page properties and vector content. Poppler emitted zero diagnostics, every expected dimension label was present, and both renderers passed the discrepancy gate.

All six final Poppler and PDFium 2000-pixel previews were visually inspected. They retain the selected labels, view captions, native geometry and material hatching; custom omissions match policy. Metadata is readable and remains clear of the title block. These inspections establish presentation review, not engineering approval. Nitro was not reopened in Phase 4; the previously tested bounded Phase 3.2 repair is reused, with its operator-preservation and renderer checks.

The FC00AAB09748 comprehensive Poppler image is pixel-identical to its Phase 3.2 reference. FC00AAB13125 preserves all 23 measurements and native datum/view placements, but its rendered pixels are not identical: unmatched dark ink beyond two pixels is 0.3379% / 0.3621%. Small painter/text/cut-label differences are retained as diagnostics; no missing characteristic was observed. It would be inaccurate to claim byte- or pixel-identical comprehensive PDF export on both parts.

## Remaining limits

Source extended Boolean failures remain 55 and 72 and remain visible in drawing notes and reports. Normalization repairs PDF serialization, not BRep defects. Thread/manufacturing semantics, unclassified complex patches and unsupported measurements still require engineering review. No materials, finishes, thread designations, tolerances or GD&T were added.

Automatic sheets start with the reviewed ANSI B layout and enlarge; they do not globally optimize all possible drafting arrangements. Fixed sheet/scale requests may fail rather than suppress meaningful dimensions. Opening details use their independently planned local scale. Configuration controls optional views, while longitudinal/right-end views remain mandatory.

Recognized candidate coverage is not dimensional completeness. The existing geometry-driven rules and synthetic fixtures remain limited evidence; additional independent vendor STEP files and other FreeCAD/OCC versions are still needed. No recognition expansion or GUI work was performed.
